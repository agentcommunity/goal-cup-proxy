# Glossary

What does word X mean here? For anyone reading or writing a doc on `m2/wire`.
Updated: 2026-10-07. Use these terms exactly; do not coin synonyms.

- **entry**: one tracked run: one harness, one goal, one workspace, one chain.
  See [ARCHITECTURE](ARCHITECTURE.md) (entry lifecycle); [D10](DECISIONS.md).
- **harness**: the coding agent program (Codex CLI, Claude Code, Hermes).
- **connector**: `connectors/<id>/`: the pinned directory (its harness manifest and the seed
  files under `files/`) that says how to launch and capture one harness. Its identity is the
  directory digest, `connector_dir_sha256` (`crates/goalcup-protocol/src/connector_dir.rs`); the
  loader is `harness::load_dir`, which returns a `LoadedConnector`.
- **harness manifest**: `connectors/<id>/harness.toml`, harness-contract schema 1: the whole
  capture recipe of one harness, parsed and refused by
  `crates/goalcup-protocol/src/harness.rs` (`HarnessManifest`).
  A harness PR adds this file, any seeds and the regenerated directory pin, and no `.rs` file.
  D42, D43; [schema reference](CONNECTOR-SCHEMA.md).
- **V1 manifest**: `connectors/<id>/manifest.toml`: the legacy, pre-schema file. During the
  feature-gated `v1-compat` product path, Codex and Claude retain one. Hermes has none, and the
  default daemon and CLI read the harness manifest. `crates/goalcup-protocol/src/manifest.rs`.
  It is not the harness manifest.
- **profile**: the `[capture]` table of the harness manifest (`CaptureSpec`): headless argv
  template, HOME/config-home mode, CA variable, provider hosts, executable pin. The V1 manifest
  has its own `[capture]` section (`CaptureProfile`), which goes with it. Its digest is
  `profile_sha256`, taken over the `harness.toml` bytes. [HARNESS-ONBOARDING](HARNESS-ONBOARDING.md).
- **shared capture home**: D39's exact `<config>/capture-homes/<connector>` leaf alias. The CLI
  validates and rechecks its leaf and canonical target identities, effective-UID ownership and
  exact target mode `0700`; it does not replace the alias spelling with the canonical spelling.
- **harness-contract schema 1 / research-report schema 1 / V1 / Decoder v1**: four different
  things. *Harness-contract schema 1* is `harness.toml` (`schema_version = 1`).
  *Research-report schema 1* is the private NDJSON report format. *V1* is the legacy product path
  and its `manifest.toml` (also the `v1/trunk` foundation, below). *Decoder v1* is the decoder trait
  and its stable public surface (`DECODER_API_VERSION`). None implies another.
- **`profile_id`**: the field `Launch.profile_id` holds a **connector id** (`hermes-cli`), not a
  profile digest. It is frozen in v5. The profile digest is `profile_sha256`, the directory digest
  is `Launch.connector_dir_sha256`.
- **origin**: loader authority, never a manifest field. `Origin::Pinned` is an in-tree or
  pin-checked connector. `Origin::Dev` is an unpinned connector selected through `--dev` and
  relaxes only the interpreter and argument-path refusals. [schema reference](CONNECTOR-SCHEMA.md).
- **pins**: (1) whole-connector directory digests in
  `crates/goalcup-protocol/pins/connector-dirs.txt`, regenerated by
  `scripts/pin-manifests.sh`; start refuses a pinned folder/id/digest disagreement. (2)
  `[capture.executable]`: exact version and SHA-256. [schema reference](CONNECTOR-SCHEMA.md#pin-evolution).
- **capture-only**: bytes recorded and not read; two current uses. (1) A stream:
  one for which the session records no accepting decoder for the full `StreamOpen`. Each decoder
  decides which fields matter; an unsupported source or content type may instead be accepted and
  emitted as `unknown`. The stream stays in the chain and the decode
  outcome lists it as `undecoded`. (2) A claim level: a harness with no registered decoder is
  claimed capture-only
  ([writing-a-decoder](../skills/adding-a-capture-harness/writing-a-decoder.md)). A harness's
  streams can still be decoded when a registered decoder accepts the full `StreamOpen`.
- **native leg**: own-session raw-file capture of the harness's own store (Codex rollout, Claude
  main JSONL, Hermes session JSON). `crates/goalcup-daemon/src/native_capture.rs`.
- **wire leg**: model traffic recorded by the process-scoped loopback proxy (`HTTPS_PROXY` plus
  a process CA), never by changing a base URL. `crates/goalcup-cli/src/proxy/`; D1 note, D36.
- **producer**: a sender of capture frames (the proxy, the native adapter), named by a producer
  id. [CONTRACTS C1](CONTRACTS.md).
- **epoch**: one admitted lifetime of a producer (`try_begin_epoch`, `try_close_epoch`). A
  restarted producer is a new epoch. `crates/goalcup-protocol/src/capture.rs` `EpochAdmission`.
- **stream**: one payload sequence inside a producer epoch. Stream zero carries the Connection,
  Recovery and Loss controls. `crates/goalcup-protocol/src/capture.rs` `StreamKey`.
- **chain**: the append-only, hash-linked protocol-v5 record file of an entry, physically
  reserved before launch. [ARCHITECTURE](ARCHITECTURE.md) (chain).
- **record**: one chained `CaptureRecord` (Open, Segment, Connection, Recovery, ProducerClosed,
  Gap, LocalFinish ...). `crates/goalcup-protocol/src/capture.rs`.
- **decoder**: a verifier component that turns the retained bytes of the streams it accepts into
  observations. The stable trait is `DecoderV1` (one fresh instance per trace, `Send`); the
  `DecoderRegistry` lists them and a `DecodeSession` runs them. A decoder that panics or fails
  stops alone. `crates/goalcup-verifier/src/capture_analysis/{api,registry,session}.rs`;
  [writing-a-decoder](../skills/adding-a-capture-harness/writing-a-decoder.md).
- **observation**: one decoded, source-referenced fact (`kind`, `fields`, the stream and parts it
  came from). Decoders emit them to an `ObservationSink`; the research report writes each as one
  NDJSON line. [m2-report-format](research/m2-report-format.md).
- **observation kind**: the closed research-report schema-1 vocabulary: `model_request`, `model`,
  `model_response`, `tool_call`, `tool_result`, `usage`, `outcome`, `error`, `unknown`, and
  `human_message`. `reasoning` is an item or field value, never an observation kind.
  `capture_analysis::api::kinds`; [m2-report-format](research/m2-report-format.md).
- **decoder finding**: a counted unknown condition reported by a decoder, such as
  `data_after_done`, `missing_done` or an `interrupted` Chat Completions end. When source-referenced
  it emits an `unknown` observation; a spanless finding increments `unknown_records` without a
  written line, so that count can exceed written observations. `KindTally` excludes emitted
  `unknown` lines; `DecoderSummary::unknown_records` owns the count. It carries no decoded fact.
  [m2-report-format](research/m2-report-format.md).
- **protocol hint**: open, grammar-validated stream metadata naming the retained-byte protocol
  (`protocol_hint`, on a `[[capture.hosts]]` or append-only `[[capture.native]]` entry; recorded as
  `CaptureMeta.protocol_hint`). The registry supplies candidates; each decoder's `accepts` receives
  the full `StreamOpen` and decides which fields matter. `hints::valid_hint` owns only the grammar;
  the `accepts` return values are the decoded-format authority. D43;
  `crates/goalcup-protocol/src/hints.rs`.
- **decoder id**: a decoder's stable implementation and report identity. It is not the hint: a
  wire decoder id may equal its hint (`openai-responses`), while a native one need not
  (`codex-native` reads `codex-jsonl`).
- **connector presentation**: the research report's OS-15 `run.connector` label: `Pinned` for a
  matching bound connector digest, `Dev/unpinned` for a present mismatch or unknown profile, and
  absent for an absent or unbound digest. It is presentation-only and never changes integrity.
- **gap**: a chained statement that bytes were lost, with a `GapReason` (QueueFull,
  ProducerLost, StorageFull, DecodeFailed, LimitExceeded, ShutdownDeadline ...). A gap makes the
  trace incomplete, never "clean". D9; `crates/goalcup-protocol/src/capture.rs`.
- **Loss**: a stream-zero frame by which the proxy reports traffic it relayed but did not
  capture (fail-open tunnel, opaque fallback, full table, unsettled cut). It is chained as a
  stream-less gap. [LEDGER](../LEDGER.md) H-16.
- **Recovery**: the record that a new producer epoch replaces a lost predecessor (wire or true
  zero-record only), with the reason. [LEDGER](../LEDGER.md) H-09.
- **seal**: ending an entry: finish, terminate owned processes, write LocalFinish and
  `seal.json`. `goalcup seal`. [TERMINATION](TERMINATION.md); D40.
- **finish budget**: the one capture budget, split into a drain share and
  `FINISH_COMMIT_RESERVE`, outside the SIGTERM/grace/SIGKILL termination bound. D40; LEDGER H-10.
- **spawn gate**: the capture child waits before `exec` until the daemon has durably registered
  it and the CLI has re-opened the exact path and streamed its regular-file reads into SHA-256. This
  streaming check is not a coherent snapshot or inode-bound execution. [TERMINATION](TERMINATION.md)
  (launcher); CONTRACTS C6.
- **anchor**: the external binding of the chain head. `AnchorState::LocalOnly` (none) or
  `Signed`. `crates/goalcup-protocol/src/capture_status.rs`.
- **LocalOnly**: no server, receipt or ACK. A valid local outcome; by itself it never lowers
  integrity exit 0. [m2-report-format](research/m2-report-format.md).
- **integrity exit**: `goalcup-verify` on a v5 trace: 0 complete and valid; 1 incomplete,
  unsealed or degraded; 2 invalid (including a torn tail); 3 no usable report.
  `crates/goalcup-verifier/src/capture_analysis/reader.rs` `exit_code`.
- **v5 freeze**: from the `v0.5.0` tag any new field on a v5 record, optional or not, is v6
  (records deny unknown fields, so a released verifier must keep reading every v5 trace).
  `FrameEvent` is outside it (`CONTROL_API_VERSION`). [CONTRACTS](CONTRACTS.md) ("The v5 format freeze").
- **reader corpus**: the committed v5 traces under `crates/goalcup-verifier/tests/fixtures/v5-corpus/`
  and their exact exits; it is what makes a verifier change that invalidates a valid trace fail CI.
- **run key**: the entry's per-run Ed25519 key. Its public half is `Launch.run_public_key`, the key
  that signs chunks and status.
- **row**: one real-harness qualification run with an exact source, binary, harness and model
  identity. [qualification/README](qualification/README.md).
- **qualified**: passed T27/T28 acceptance. Nothing on `m2/wire` is qualified yet.
  [LEDGER](../LEDGER.md) T27, T28. Say "built" for code that exists; "measured" needs a record.
- **V1 / V1.1 / M2**: V1 is the `v1/trunk` foundation pinned `7f01234`/`v0.1.0`; V1.1 is its
  product expansion ([D29](DECISIONS.md#d29-v1-is-the-defined-foundation-qualification-target-v11-is-product-and-event-expansion));
  M2 is this branch's [wire-plus-native recorder](ARCHITECTURE.md#4-the-two-legs).
