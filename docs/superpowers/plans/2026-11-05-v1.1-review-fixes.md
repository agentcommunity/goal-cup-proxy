# v1.1 Review Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the small, verified findings of the 5-lane review of v1.1.3 (participant messages, stale docs, quiet test gaps) in five parallel cloud lanes, then prove the merged result on the owner's Mac. No version bump, no tag.

**Architecture:** Five lanes, each owning a disjoint set of files, so they run at the same time in separate cloud sessions and merge in any order. Each lane opens one PR to `main`. A local Mac session (the orchestrator) starts the lanes, reviews each PR, merges, and runs the full gate plus a short hand check of the new messages.

**Tech Stack:** Rust (workspace `goalcup`, `goalcup-verify`, `goalcup-format`), POSIX sh (`scripts/gate.sh`), Python 3.9+ (`scripts/pad/*`), Markdown docs.

**Spec:** the review report of 2026-11-05 (5 lanes on tag `v1.1.3`, `ccbdb19a`), summarised per task below. Read `VISION.md` and `AGENTS.md` before any lane.

## Global Constraints

- No version bump: do not edit `Cargo.toml` `[workspace.package] version`, `Cargo.lock`, or any tag. No release.
- Each lane touches only the files in its own **Files** block. If a lane needs another file, it stops and reports.
- Run `sh scripts/gate.sh fast` (or the named `--part`) before every push; push only when it passes.
- Never open `.env`, `.env.local`, `.dev.vars`, `~/.pad-keys`, or anything in `~/.claude`, `~/.codex`, `~/.hermes`.
- No network calls to staging or production. No `wrangler deploy`. No real harness runs in cloud lanes.
- Participant text is plain English, short sentences, one word per thing: say "harness" (or "agent" where the CLI already does), never "connector", in anything a participant reads.
- Less code is better: cut before you add.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Branch names: `fix/review-<lane letter>-<short>` from `origin/main`. One PR per lane, base `main`.
- Out of scope (owner decisions, do not change): run length (168 h) and the start window, video deadlines in `docs/RULES.md` §videos, `server/worker/wrangler.toml` values (`EVENT_ID`, `DEVICE_*_PER_MINUTE`), anything in `TODO.md` "after 1.0" beyond Task B2's rewrite.

## How the orchestrator runs this (local Mac session)

1. Start five cloud sessions at once (`start_session`, `target: "cloud"`, `context: "fresh"`), one per lane A–E. Each starts from `main`. Brief for lane X:
   > Execute **Lane X** of the plan `docs/superpowers/plans/2026-11-05-v1.1-review-fixes.md` on branch `plan/v1.1-review-fixes` (`git fetch origin plan/v1.1-review-fixes && git show origin/plan/v1.1-review-fixes:docs/superpowers/plans/2026-11-05-v1.1-review-fixes.md`). Read its Global Constraints first. Work on a new branch `fix/review-x-<short>` from `origin/main`; touch only your lane's files; use subagent-driven development per task (Sonnet implementers, one reviewer per task); run `sh scripts/gate.sh fast` before pushing; open one PR to `main` titled `review fixes: lane X — <topic>`; then run /requesting-code-review on your own PR and fix what it finds. Do not merge.
2. Cloud sessions do not report back: watch for the five PRs with `gh pr list --search "review fixes: lane"`.
3. When all five are open and CI is green, run Task M1 here on the Mac.

Lane A changes `crates/goalcup/src`, a guarded path: the next release will need fresh pad rows. That is fine; there is no release in this plan.
