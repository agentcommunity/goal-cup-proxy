# Fix plan v9, 2026-10-22 (time-left as a tool the agent calls)

Owner, 22 Oct 2026: "time left - isn't this a tool that the app can call, not a skill, or a skill too
but it should be a tool the agent can call up. so doesn't matter where the agent path is it can just
call it (like a micro api endpoint or mcp endpoint)". Context: in a Docker Codex cell the agent's
`goalcup time-left` failed with `goalcup: not found` (Codex runs commands in a login shell that
resets PATH). Time-left must not depend on how a harness builds its PATH. Draft for owner review:
stays on its branch until the owner approves.

## Design
- `goalcup mcp`: a minimal MCP server on stdin/stdout (JSON-RPC 2.0: `initialize`,
  `notifications/initialized`, `tools/list`, `tools/call`, `ping`), one tool `time_left` (no
  arguments) that reads the run's time-left file (the one D66 defines and `goalcup time-left` reads)
  and returns the same sentence `goalcup time-left` prints. Read-only: it cannot seal, stop, continue
  or change anything (AGENTS.md "no finish tool"). No network port. No new crate dependency (serde
  is in the tree).
- The harness starts it by absolute path, so PATH does not matter.
- Goal Cup never writes it into a harness's config (D67). `docs/HARNESS-SETUP.md` gets a section "Add
  the Goal Cup time-left tool" with the exact config snippet per harness (Codex `config.toml`
  `[mcp_servers.goalcup]`; Claude Code `claude mcp add` / settings; Amp settings `amp.mcpServers`;
  Hermes `config.yaml` `mcp_servers`), each using the participant's absolute goalcup path; mark
  snippets not tried live as "not measured". `goalcup prep` prints the snippet for the chosen
  harness with the absolute path filled in, and changes nothing.
- Fallbacks unchanged: `goalcup time-left` and the time-left file named in the environment. The
  goal-cup skill mentions the tool first.
- What the record shows: an MCP call over stdio is not on the wire; the harness's native session
  shows the tool call. Say so in the guide.

## Tests
- Protocol: `initialize` answers with the server's name/version and tools capability; `tools/list`
  lists exactly `time_left`; `tools/call time_left` returns the same text as `goalcup time-left` for
  a fixture time-left file (running, practice, ended, no run); unknown method and unknown tool give
  JSON-RPC errors; malformed input does not crash; EOF exits 0.
- It never writes any file (run it in a read-only fixture directory).
- prep prints the snippet with the absolute path for a connector that names its config format.

## Done when
`sh scripts/gate.sh fast` passes; a manual JSON-RPC exchange with the built binary returns the time
left; the owner approves before merge.
