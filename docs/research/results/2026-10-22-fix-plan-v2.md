# Fix plan v2, local test day 2026-10-22 (after the 10-minute smokes)

v1 ([fix plan](2026-10-22-fix-plan.md)) is merged (9fec42e6). This plan follows the eight
staging practice smokes (Mac host and Docker, Codex, Claude Code, Amp, Hermes) and their
analyses. One implementer works it in its own worktree; the supervisor reviews and merges.

## What the smokes showed, together

| Cell | Matrix row | Real agent work | Cause when not |
|---|---|---|---|
| mac-codex | PASS | yes, 0 commits | Codex sandbox: `.git` read-only, then an approval prompt nobody answers (owner decision, not here) |
| mac-amp, mac-hermes, lx-hermes | PASS | yes | none |
| lx-codex | PASS | **no** | the prompt arrived as a split paste and the Enter became a newline |
| lx-amp | PASS | **no** | Amp's welcome screens took the typed prompt (an environment seed; fixed) |
| mac-claude, lx-claude | FAIL (gaps) | **no** | a Claude Code dialog took the prompt; every Anthropic reply is brotli, which the proxy cannot decode |

Two threads run through it:

1. **The recorder cannot read Claude Code's replies.** `api.anthropic.com` answers
   `content-encoding: br` whenever the request offers `br` (measured with curl on 22 Oct: offered
   `gzip, deflate, br, zstd` -> `br`; `gzip, deflate` -> none; `zstd` alone -> none). The proxy
   decodes identity, gzip, x-gzip and deflate only (`crates/goalcup-cli/src/proxy/http.rs`
   `Decoder::for_codings`), so each reply is an `unsupported_encoding` gap and every Claude Code
   run is "capture integrity incomplete". The coverage matrix already shows Claude runs
   "incomplete (3 gaps)" and "Claude inference remains deferred": this is that cause.
2. **The kit types into whatever screen is up and then passes the row anyway.** A paste split by
   the pty, a first-run dialog or a welcome screen each swallowed the prompt, and the row still said
   PASS because nothing checks that the agent worked.

## Items, in order

### K5. The proxy decodes brotli (product; dependency for review)
- Decode `br` in `Decoder::for_codings` with a decode-only, pure-Rust crate
  (`brotli-decompressor`; no encoder, no C). `cargo fetch` once to add it to Cargo.lock; keep
  `scripts/third-party-licenses.py` and the license gate green. `zstd` is already a dependency:
  decode `zstd` too (cheap, same place), since a harness may offer it.
- A gap for a coding still not decoded names the coding (`unsupported_encoding` gains the
  content-coding token list, bounded), so the next unknown is diagnosable from the trace alone
  (`crates/goalcup-protocol` capture types and the verifier's reading of gaps; schema rules in
  docs/CONTRACTS.md: add a field only in a backward-compatible way, or put it in the existing
  detail text if the schema has one).
- Tests: a br-encoded and a zstd-encoded response stream decode with no gap; a multi-coding or
  unknown coding still gaps and names the coding. The owner reviews the dependency in the PR.

### K6. The kit delivers the prompt as one bracketed paste
- `scripts/matrix.sh` (the feeder near line 890) wraps the prompt in `ESC[200~ ... ESC[201~`
  when the harness has switched bracketed paste on (`ESC[?2004h` seen in its output before the
  prompt), then waits `MATRIX_SUBMIT_DELAY`, then sends Enter. Without it, keep today's behaviour.
- Tests (scripts/test_matrix.py, the fake TUI): a TUI that enables bracketed paste gets the
  wrapped prompt; one that does not gets the raw keys.

### K7. A matrix row needs the agent to have worked
- For a real connector, after `verify_trace`: `goalcup-verify --research-json` (same `--dev-key`
  fallback) must show at least one model exchange that carries output (a usage observation with
  output or completion tokens above 0, or a decoded assistant message). Otherwise the row FAILs
  with "the agent never answered the prompt". `linux-matrix.sh`'s owner-rule failure must also
  turn the row into FAIL instead of printing the PASS row first (lines ~466-472).
- Validate locally on today's kept traces before relying on it: must pass mac-codex, mac-amp,
  mac-hermes, lx-hermes; must fail lx-codex, lx-amp (paths in the results file). Tests with
  synthetic research reports.

### K8. Claude Code's first-run dialogs and Amp's welcome in the kit's home config
- `scripts/kit_settle.py home-config` gains, for claude-code-cli, whatever state stops the
  "Try the new fullscreen renderer?" dialog from appearing (find the key in the installed Claude
  Code's own state files or bundle; an answered "Not now" must not change the renderer) and, for
  amp-cli, `agentMode: "low"` and `neoWelcomeDismissed: true` in the run home's
  `.local/share/amp/session.json` (merge into an existing file; never touch accounts.json or
  secrets.json). Keep the trust-dialog keys as they are.
- Tests: the home gets the keys, other keys kept, login files never read.

### K9. Small ones
- Campaign starts are spaced: `campaign.py run` starts at most one cell per 30 s (staging allows
  5 device starts per minute per address; 8 cells at once got HTTP 429). Test with the fake clock.
- The matrix row's version field keeps the version line's first token (Amp prints
  `0.0.x (released <date>, 4d ago)`, cut at 64 bytes and different every day). Kit only; the
  product's `harness_version` stays as D53 says.
- `goalcup time-left` in a practice run does not say "Push your work often" (a practice clone
  cannot push). Find the text in crates/goalcup-cli; test the practice wording.

### K10. macOS: a root caught while exiting is not "recycled" (daemon)
- mac-amp and mac-codex sealed `Unresolved{ProcessAuthorityUnavailable}` although the harness
  exited (daemon.log: `still_alive=[] observed_gone=false harness_unverified=true`). For about
  30-45 ms after death a macOS process shows state `E` in `ps` (so `liveness` says live,
  `goalcup-protocol/src/process.rs` ~489 excludes only `Z`) while `proc_pidinfo` already fails, so
  `guard_registered` (`crates/goalcup-daemon/src/terminate/authority.rs` ~394-406) refuses the root
  as recycled. Claude Code is unaffected (single process, kqueue path).
- Fix: when the start identity cannot be read but the process still reads live, re-ask
  `liveness` every 5 ms up to `EXITING_ARGV_WAIT` (200 ms), as `exited_or_renamed` does; "no longer
  live" is `Absent`; refuse only if still live at the end. Let `no_readable_argv` (~452) accept the
  macOS `(comm)` form. Document the exiting window in docs/TERMINATION.md (macOS section); update
  docs/harnesses/amp-cli.md (~28) and docs/CHEAT-CHECKLIST.md (~72).
- Test (macOS): a multi-process tree whose root is SIGKILLed while exiting seals `Confirmed`; a
  root still live after the wait is still refused (fail closed stays).
