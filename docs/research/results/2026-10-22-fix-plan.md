# Fix plan, local test day 2026-10-22 (v1)

Findings from the local test day ([results](2026-10-22-local-test-day.md)), considered together
before any fix. One implementer works this plan in its own worktree; the supervisor reviews and
merges it into `smart/zen-gates-d9tmbh`. Already fixed before the plan (ea5c30f9): the reserve
test asserted the wrong thing, `campaign.py build` refused before the host sign-ins,
`check-sql.sh` needed `LC_ALL=C` on macOS.

## What the findings have in common

The kit (scripts/matrix.sh, linux-matrix.sh, campaign.py) and the CLI drifted apart on one point:
what a TEST run needs from GitHub. Since 663b50ed a competition or test start asks GitHub, with
the stored token, whether the repository is empty (`commands/start/refusals.rs`
`refuse_used_repository` → `account/github.rs` `check_empty`). The kit still writes a fake token
for test runs ("never sent anywhere") and only for Docker cells. And the docs still say full-flow
repositories are private, which `prep`, the clone and the Worker all refuse. The CLI is right; the
kit and docs follow it. No CLI change (an anonymous fallback in `check_empty` was considered and
rejected: an expired participant token would then start a competition run whose pushes fail for
hours, RULES "judged commit").

## Items, in order

### K1. One token file for test cells (blocker)
- `campaign.py`: config key `defaults.github_token_file` (absolute path, regular readable file,
  like `approval_key_file`; never opened by campaign.py, never in argv). `check`/`run` refuse a
  test cell without it.
- One settle helper, `scripts/kit_settle.py` (stdlib Python): given CFG, WORK, REPO_URL and the
  token file, writes `prep.json` (`repo_url`, `work_root`, keeps other keys) and `github.json`
  (`repo_url`, `token`), both 0600, atomically. A `prep.json` whose `repo_url` is a prep'd
  full-flow repository (not the practice repo) is kept as it is, with its `github.json`.
- Docker: `linux-matrix.sh` mounts the token file read-only (as the approval key:
  `-v <file>:/run/goalcup/github-token:ro`), `inner_settle` calls the helper. Env name
  `MATRIX_GITHUB_TOKEN_FILE` (path only).
- Host: `campaign.py login` runs the helper after `goalcup prep --harness X`, and `run` runs it
  before each host cell (so a token rotated later is picked up).
- matrix.sh's own fake token (OWN_CONFIG, practice only) stays: practice starts skip the check.
- Safety line in the docs: the kit token must not be able to push to the practice repository
  (one agent push there would make every later test start refuse it).
- Tests (scripts/test_campaign.py, test_linux_matrix.py): the token reaches github.json 0600 and
  is never in argv, env values or logs; a test cell without the file is refused before anything
  starts; a prep'd full-flow repo is kept; host login leaves both files.

### K2. Cheapest-model rules and the model check for host cells
- Today only Docker cells get Codex `gpt-5.6-luna`/`low` and Claude Code `haiku`/thinking off
  (`linux-matrix.sh inner_home_config`) and the model check after the run (`inner_model_check`).
  Move both Python bodies into `scripts/kit_settle.py` (or a sibling) and call them from
  linux-matrix.sh (inside the container) and from campaign.py for host cells (before the run;
  the check after it, failing the cell like Docker does).
- Tests: a host cell's homes get the settings; a turn on another model fails the cell.

### K3. Hermes reports its version
- `connectors/hermes-cli/harness.toml` has no `version_args`, so every Hermes row says
  `unreported` (measured on Mac and Docker). `hermes --version` prints
  `Hermes Agent v0.19.0 (2026.7.20)` in under a second with a fresh HOME (it writes only
  `.hermes/.update_check` and logs there, which the probe home discards). Add
  `version_args = ["--version"]` and regenerate pins (`sh scripts/pin-manifests.sh`) in the same
  commit. Test: the connector check passes; the existing version-probe tests cover the rest.

### K4. Docs that are now false (one pass, after K1 to K3)
- LOCAL-TEST-DAY: full-flow repos are PUBLIC (`gh repo create ... --public`); staging
  `GITHUB_TOKEN` needs no private access; infrastructure cells are test runs that send the token
  (not "anonymous"); "read the test test repositories" typo; the ground rule "Never set a model
  base URL" means Goal Cup never sets one; Hermes's own `config.yaml` needs `model.base_url`
  (D62), which `prep` asks for; WSL2 needs a Windows machine (say how to skip it).
- LOCAL-CAMPAIGN: "Cells" and `campaign.example.json` get `github_token_file`; the fake-token
  wording goes; build before login now works.
- OPERATING "The matrix": `--test` needs a real token in github.json; `MATRIX_GITHUB_TOKEN_FILE`.
- Comments: linux-matrix.sh `inner_settle` ("never sent anywhere"), its `[todo] github ...
  expected` lines.
