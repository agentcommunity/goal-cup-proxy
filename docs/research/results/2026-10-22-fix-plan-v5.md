# Fix plan v5, local test day 2026-10-22 (Codex loses PATH in a login shell)

After [v4](2026-10-22-fix-plan-v4.md) (merged 15fb4163). In the Docker cell lx-codex, Codex ran
`goalcup time-left` and got `/bin/sh: 1: goalcup: not found`; Claude Code in the same kind of cell
found it.

## Cause (measured 22 Oct)

- Goal Cup hands a chat-mode harness the participant's own PATH (`crates/goalcup-cli/src/launch.rs`
  ~809, `harness_path` ~334) and a private, empty run HOME (~808). Correct so far.
- Codex 0.153 runs every command as `/bin/sh -lc "<cmd>"` (the run's rollout shows it; the shell
  comes from `/etc/passwd`). A login shell runs `/etc/profile`, which on Debian/Ubuntu sets
  `PATH="/usr/local/bin:/usr/bin:/bin:..."` outright; `~/.profile` would add `~/.local/bin` back,
  but the run HOME is empty. Reproduced: `sh -lc` and `bash -lc` lose the directory, `sh -c` keeps
  it. macOS's `/etc/profile` (`path_helper`) keeps the PATH, so the Mac cells worked.
- So a real Linux participant who installed with `install.sh` (`~/.local/bin`) loses `goalcup`
  (and `~/.cargo/bin`, nvm, ...) inside Codex's commands: `goalcup time-left` fails, D57's promise
  that the agent gets the participant's PATH is broken. Claude Code uses no login shell.

## Items

### Q1. The run HOME restores the PATH Goal Cup handed the harness (product)
- When Goal Cup makes the private run HOME for a chat-mode connector, it writes `.profile` (and
  `.bash_profile` that sources it, for `bash -l`) holding one line that exports the PATH it handed
  the harness (shell-quoted). This repairs what Goal Cup's own empty HOME took away; it changes no
  harness setting (D67) and no connector argument (D57). Do not write it if the file exists.
- Not chosen: `-c allow_login_shell=false` in the codex-cli connector (it changes Codex's behaviour,
  which D67 says Goal Cup does not do). Owner to confirm the choice in review.
- Tests: a run HOME gets the files with the exact PATH; `sh -lc 'command -v <marker>'` finds a marker
  binary from that PATH in a test with a fake `/etc/profile`-style reset (Linux-only test where
  needed); an existing file is kept.

### Q2. Backstop in the goal-cup skill (docs)
- `skills/goal-cup/SKILL.md` (~22): if `goalcup` is not found, read the time-left file named in the
  environment variable Goal Cup sets (`launch.rs` ~841-843) instead.

### Q3. The kit installs goalcup like a participant (kit fidelity)
- `scripts/linux-matrix.sh` (~667): put the binaries in the `dev` user's `~/.local/bin` (as
  install.sh does) and stop prepending `/target/debug` to the container PATH for the harness, so a
  Docker cell reproduces a real install. Tests in test_linux_matrix.py.
