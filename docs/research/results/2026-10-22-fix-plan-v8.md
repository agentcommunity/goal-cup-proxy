Owner, 22 Oct 2026: "all the change setting on the harness will have to be done by the user, we
don't change settings. We could have the setup CLI give tips or a link to a page we host where we

## Item T1. `docs/HARNESS-SETUP.md`: "Set up your harness for a 168-hour run"

One page, written for a participant (plain words, Simplified Technical English as the other
participant docs), one section per topic, each with a per-harness table (Codex, Claude Code, Amp,
Hermes) saying the exact setting, where it lives (in the Goal Cup home `goalcup prep` opens), and
what happens without it. Every fact from the measured harness docs and the test-day results; mark
anything not measured as such. Topics, from what stopped agents on 22 Oct:
1. Run without permission prompts (answering one is typing; RULES allow only "keep going"):
   Codex `approval_policy`/`sandbox_mode` (its sandbox cannot start in a container without user
   namespaces); Claude Code `permissions.defaultMode` plus its one-time acceptance, and the
   follow-up offers it shows at start (trust, fullscreen renderer, auto-mode default); Amp and Hermes.
2. Commits and pushes: the agent must be able to write `.git` and push (Codex's default sandbox
   makes `.git` read-only).
3. Turn and iteration limits: Hermes `agent.max_turns` (default 90 stopped agents after minutes).
4. Sign-in lifetime: sign in at prep; what happens when a token expires during the run.
5. Subagents and their models (Amp's Task subagents ran a larger model than the thread's mode).
6. Your tools on PATH: Goal Cup hands the harness your PATH; a login shell may reset it (Goal Cup's
   run home restores it since v5).
7. First-run screens to answer once during `goalcup prep`, never during the run.
Link it from README (participants), the participant guide, RULES ("keep going" line) and each
`docs/harnesses/<id>.md` "Run without permission prompts" section.

## Item T2. `goalcup prep` links to the guide
- The recommendation line prep prints (v4 P4, connector `[[participant.no_prompts]]`) points to the
  guide's section for that harness, and prep's harness step prints one line pointing to the guide
  even when nothing is missing ("Before a long run, read docs/HARNESS-SETUP.md"). Never changes a
  setting, never fails prep. Connector data edits regenerate pins. Tests for the wording.
