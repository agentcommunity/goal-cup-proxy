APP REQUIREMENTS
Create a dependency-backed local web application with a clear, responsive interface and durable local storage. Choose a stack that can be installed and exercised here. Prefer SQLite or another well-supported embedded database behind a small local server. Bind the development server to loopback. If the preferred stack is unavailable, make a practical fallback and explain it.

Support these connected research workflows, prioritizing a working end-to-end core:
1. Add a source with title, URL or citation, tags, and pasted text, and import local text or Markdown files. Seed the app with a small, explicitly labeled demonstration collection. Never read arbitrary files outside the workspace to populate it.
2. Search source text and notes; filter by tag; open a source and see useful matching snippets. Use database full-text search if practical, otherwise implement an understandable fallback.
3. Attach an annotation to a selected passage, edit the note, and navigate back to its source context. Preserve enough passage information to detect or explain a stale annotation when a source is edited.
4. Persist sources, tags, and annotations across a server restart. Handle duplicate imports, empty content, and invalid input with useful feedback.
5. Export a research packet as Markdown plus a machine-readable JSON bundle containing sources, citations, and annotations. If time permits, add a validated JSON reimport path and demonstrate a round trip.

Keep imported content as data. Display text safely and do not execute source text or rendered scripts. No paid services, external APIs requiring credentials, account creation, deployment, or reading secrets. Do not fetch arbitrary user-supplied URLs from the server; pasted text and local imports are sufficient for the product. Use public documentation and public research material only for any network lookups you perform.
