# "One TLS proxy for all harnesses" — feasibility research for the /goal Cup tracker

Date: 2026-09-10. Scope: launch each harness with process-scoped env (`HTTPS_PROXY=http://127.0.0.1:PORT` + a per-runtime CA-trust env var), terminate TLS locally, record raw provider-API bodies, parse per *provider* wire format instead of per *harness* transcript format. Base URLs untouched so subscription/OAuth auth is unchanged.

Labels: **Verified** = vendor doc, source, or issue at the cited URL says it. **Inferred** = derived from runtime behavior / adjacent evidence. **Unknown** = no evidence found.

Local evidence used (read-only): `claude` 2.1.259 native binary (Bun v1.4.1 embedded; strings contain `HTTPS_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`, `NODE_USE_SYSTEM_CA`, `CLAUDE_CODE_CERT_STORE`, undici `ProxyAgent`/`EnvHttpProxyAgent`, `OTEL_LOG_RAW_API_BODIES`; the only `wss://` targets are `bridge.claudeusercontent.com`, i.e. the Chrome/Remote-Control bridge, not model calls). `codex` 0.143.0 Rust binary (strings: `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`/`NO_PROXY`, `CODEX_CA_CERTIFICATE`, `SSL_CERT_FILE`, `rustls`, `webpki`, `tungstenite`, `responses_websockets`, `supports_websockets`, `reasoning.encrypted_content`, `store`; links only Apple system frameworks, no OpenSSL). `/Applications`: Claude.app 1.49585.0 (Electron), ChatGPT.app 26.901 (Swift/Sparkle, bundles `Resources/codex` and `codex-code-mode-host`), Cursor.app 3.19.19 (Electron). OpenCode, Hermes, OpenClaw, cursor-agent, gemini are not installed here.

## 2. Cross-cutting findings

### 2.1 What "everything the model sees" actually means on the wire
- **Input side is complete** for every direct-to-provider harness: system prompt / instructions, full message history, tool definitions, tool results, `model` id, and all prior assistant blocks (including `signature` / `encrypted_content` blobs that are round-tripped verbatim). This is exactly the evidence needed to prove no human injected text after the initial prompt.
- **Raw chain-of-thought is not on the wire anywhere** and this is not a proxy limitation:
  - Anthropic: thinking blocks are summaries at best; on Opus 4.7+/Fable/Mythos the default is `display:"omitted"` (empty `thinking`, encrypted `signature` only); "No `display` setting returns the raw chain of thought." (thinking doc above). `OTEL_LOG_RAW_API_BODIES` additionally redacts thinking.
  - OpenAI Responses: Codex/OpenCode use `store:false` + `reasoning.encrypted_content` → opaque blob; summaries optional.
  - Gemini: thought summaries + `thoughtSignature`.
- **Streaming**: Anthropic and Gemini stream SSE over HTTP/1.1 (Bun `fetch` is HTTP/1.1; LocalAI's proxy negotiates h2 and falls back). Codex under ChatGPT auth streams over a **WebSocket**; the recorder must log WS frames (mitmproxy does) or the tracker must force HTTP via a `CODEX_HOME`-scoped `config.toml` with `supports_websockets=false`.
- **Subagents**: Claude Code Agent tool, Codex `spawn_agent`, OpenCode/Hermes/OpenClaw sub-runs are all in-process or child processes → captured. Exceptions: Claude Code background supervisor (`--bg`, `claude agents`, `/background`), OpenClaw's launchd Gateway, Hermes `gateway` service, `opencode serve` daemons.

### 2.2 Processes that would NOT inherit the env (hard list)
1. Claude Code background-agent supervisor (documented: shared per-user daemon; OS-installed variant gets no shell env).
2. OpenClaw Gateway under launchd/systemd (default) — CLI/TUI only attach over WS.
3. Claude Desktop (LaunchServices), its Cowork VM, and its Code-tab subprocess.
4. ChatGPT/Codex desktop app (LaunchServices).
5. Cursor IDE (LaunchServices) — and irrelevant anyway (backend-mediated).
6. Hermes iron-proxy sandboxes (env deliberately rewritten).

### 2.3 Non-HTTP / MITM-hostile transports
- Codex Responses WebSocket (default with ChatGPT auth): CONNECT-tunnelled since PR #31441; known flakiness → automatic HTTPS fallback, so the recorder must handle both.
- Cursor: HTTP/2 Connect/protobuf to Cursor's own backend; MITM-able but content is not the provider wire format.
- Claude Code: no WS for model calls (only the Chrome/Remote-Control bridge). No gRPC found. HTTP/1.1.
- Bun-based harnesses (Claude Code, OpenCode): Bun `fetch` over HTTPS-through-CONNECT had a body-corruption bug (oven-sh/bun#30381) — must be regression-tested against the tracker's proxy implementation.

### 2.4 Terms of service (factual, not legal advice)
- **Anthropic Consumer Terms** (https://www.anthropic.com/legal/consumer-terms): prohibit decompiling/reverse-engineering "our Services", scraping/harvesting, and automated access "except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it". No clause addresses a user observing their own client's traffic.
- **Claude Code legal & compliance** (https://code.claude.com/docs/en/legal-and-compliance), "Authentication and credential use": OAuth is "designed to support ordinary use of Claude Code and other native Anthropic applications"; developers "may not collect, store, or intermediate Claude.ai credentials or session tokens" and may not "route requests through Free, Pro, or Max plan credentials on behalf of their users"; separately "The Claude Code binary must not be modified" (in the hosting section). A passive local proxy does not modify the binary, does not change the base URL, and does not reuse the token — but **the captured request headers contain the OAuth bearer token**, so the tracker must strip `Authorization`/`x-api-key`/cookies *before* anything leaves the machine, otherwise organizers would be "collecting/storing" credentials. Anthropic explicitly documents TLS-inspection proxies as supported (network-config doc), which is the same mechanism.
- Distinguish from the Jan–Apr 2026 enforcement against **using consumer OAuth tokens in third-party harnesses** (OpenClaw, OpenCode, Hermes' direct path): https://www.theregister.com/2026/02/20/anthropic_clarifies_ban_third_party_claude_access/ . Anthropic's detection is system-prompt pattern matching, not headers/TLS (gist above), and the proxy-marker code keys on `ANTHROPIC_BASE_URL` (unset in this design).
- **OpenAI Terms of Use** (https://openai.com/policies/row-terms-of-use/): no reverse-engineering; no "automated or programmatic method to extract data or output… (except as permitted through the API)". OpenAI simultaneously documents `CODEX_CA_CERTIFICATE` for corporate TLS proxies and publicly welcomes ChatGPT-plan use in third-party harnesses (https://manifest.build/blog/chatgpt-plus-tokens-third-party-harnesses/). No source addresses a personal local MITM specifically.

## 3. Verdict

**Works today with process-scoped env only** (ordered by confidence): Claude Code CLI (docs-blessed; HTTP/1.1 SSE; in-process subagents) → Codex CLI (docs-blessed CA + proxy incl. WSS since July; needs WS-aware recorder or `CODEX_HOME` config to force HTTP) → OpenCode (Bun honors env; needs `NO_PROXY=localhost,127.0.0.1`; ChatGPT plan only) → Gemini CLI (env or `--proxy`; internal `cloudcode-pa` envelope) → Hermes (httpx honors env; CA support unstable; Claude path is policy-violating anyway) → OpenClaw (only if the tracker runs `openclaw gateway` in the foreground; `openai-completions` bypass bug).

**Hard blockers**: Cursor CLI + Cursor IDE (backend-mediated; provider bytes never reach the client); Claude Desktop (Chromium CA needs keychain; Code tab drops env); ChatGPT/Codex desktop (LaunchServices env, Swift side, config ignored); any harness's daemon mode (Claude Code `--bg` supervisor, OpenClaw launchd Gateway, `opencode serve`, `hermes gateway`).

**Raw reasoning is not recoverable by any method** (summarized/omitted/encrypted at the provider), so the tracker's claim should be "complete model *input* + complete model *output as delivered to the harness*", which is sufficient for the no-human-help guarantee.

**Single biggest unknown**: nobody has published a 168-hour run of a subscription-authenticated harness through a local TLS-terminating proxy. Specifically: (a) whether Codex's WSS-over-CONNECT path (PR #31441, merged two months ago) stays stable or silently flips to HTTPS mid-run, and (b) whether the proxy's *upstream* TLS fingerprint (differs from Bun/rustls) or Anthropic's evolving client-integrity checks ever reject or throttle the session. Both are testable in a day; neither is answerable from documentation.
