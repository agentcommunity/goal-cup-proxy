## The finding that matters

Every target harness already writes a complete, model-visible transcript to local disk, and every one has a hook or plugin surface. No proxy is needed. The tracker's job is therefore not to intercept the model; it is to **tail, hash-chain, and ship** what the harness already writes, and to cross-check it against an independent hook stream.

Claude Code additionally has a first-party, documented way to dump byte-exact API request and response bodies to disk (`OTEL_LOG_RAW_API_BODIES=file:<dir>`), verified today on v2.1.258 with subscription OAuth. That is the strongest single evidence source of any harness.

## What this changes in the tracker design

1. **Connectors become thin.** A connector is: (a) where the harness writes and how to parse it into the neutral format, (b) a hook/plugin recipe to install for the independent witness stream, (c) the launch recipe that pins env/flags (`OTEL_LOG_RAW_API_BODIES`, `--settings`, `compression: 'none'`, `DSH_TELEMETRY_DISABLED`, fixed `--port`). The Rust core owns tailing, hash chain, encryption, upload, acknowledgement, and the verifier. This is what makes 20+ harnesses before T0 realistic.
2. **Two independent legs per harness, reconciled.** Leg 1: the harness's own persisted transcript (tailed, hashed per line, shipped). Leg 2: the hook/plugin stream (posted to the tracker). The seal fails if they disagree. This is the defence against "disable hooks, then replay" and against edited transcript files, since the participant would have to forge both consistently and before the next server acknowledgement.
3. **Hooks are disableable everywhere.** Claude Code, Cursor, OpenClaw hot-reload; Codex, Hermes, dsh reload on restart, and a restart is exactly what `keep going` after a crash looks like. So hook silence during an active transcript is itself a flag, and the transcript leg, not the hook leg, is the integrity anchor.
4. **Server acknowledgement is the only thing that turns a local chain into evidence.** No off-the-shelf tool does this for agent logs (DEPOSE is closest: hash chain + Ed25519 + RFC 3161, AGPL, no server anchor). Build a small ack service; optionally anchor the final seal in Rekor v2 as a DSSE entry.
5. **Normalize to ATIF v1.8** (Harbor / Terminal-Bench's mandatory trajectory format), keep raw files hash-referenced. Harbor already has Claude Code and Codex converters to crib from.
6. **The "human typed this" test is harness-specific and must be documented per connector.** OpenCode has no marker at all (anything non-synthetic is client input) — and the rule needs two extra scopings, `session.parent_id IS NULL` and `session.directory == <workspace>`, because the task tool's prompt to a subagent is an unmarked `role=user` message and the database is home-wide [verified 2026-09-03 spike 5]; **Codex has no marker at all on 0.153** — the `user_message` event this line used to cite does not exist, human and harness text share one `role=user` shape, and subagent rollouts replay the parent's human turns, so the rule needs file scoping plus hook corroboration [verified 2026-09-03 spike 2]; dsh has `source.kind`; Claude Code needs three sources to agree; **OpenClaw leaves plain local input entirely unstamped** — `provenance` is present only on harness-authored user-slot text, so the rule is "provenance absent, no `__openclaw.transport`/`senderId`, no `__openclaw.beforeAgentRunBlocked`" corroborated by a leg-2 `ctx.trigger:"user"`, and it must be scoped by `ctx.sessionKey` because the store is agent-wide and `ctx.workspaceDir` always reports the Gateway's workspace [verified 2026-09-03 spike 8].
7. **A second untracked agent in the same workspace is the residual gap for every harness.** Only workspace tree hashes taken at each tool call (git `write-tree` after `PostToolUse` equivalents) make unexplained file changes visible. This is the one piece of core evidence that is not "tokens", and it is cheap.

## Rules consequences to carry into RULES.md

- Ban cloud/remote modes explicitly: Claude Code on the web, Codex cloud, Cursor cloud/background agents, OpenCode GitHub actions, remote Hermes/OpenClaw servers, dsh E2B sandboxes.
- Ban ephemeral/no-persistence flags: Codex `--ephemeral`, Claude `--no-session-persistence` / `CLAUDE_CODE_SKIP_PROMPT_HISTORY`, OpenClaw incognito and `agent exec`, Hermes `--safe-mode` until verified, OpenCode `--pure` / `OPENCODE_PURE=1` and `OPENCODE_DISABLE_PROJECT_CONFIG=1` (both skip the folder-scoped shim, verified present on 1.18.27), plus `POST /instance/dispose` / `POST /global/dispose`, which reload plugins mid-run.
- Remote Control and chat-channel inputs (Claude Code Remote Control/Channels, OpenClaw channels, Hermes gateway) are observable but are additional human-input paths; either ban or treat every message from them under the `keep going` rule.
- Pin harness versions per connector for the event window; every harness's on-disk format is documented as unstable (Claude Code explicitly, dsh at v0 with daily alphas).
- Require dedicated app-actor identities for external services the agent writes to (Linear `actor=app`, GitHub App tokens, Slack bot user) so human mutations are distinguishable.
