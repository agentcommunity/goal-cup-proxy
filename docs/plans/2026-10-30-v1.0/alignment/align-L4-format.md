## Checked and found aligned

- **F1, new format.** PRD-01 decisions and sections 1, 3, 7, 9 (lines 18-29, 57-69, 183-245, 319-389): one
  `ws_up` and one `ws_down` stream per WebSocket connection, raw bytes (no base64, no JSON number arrays),
  light binary framing, gaps with start and end and lost bytes, `recorder_down` off spans, COUNT of written
  records, counts at the durable LINK only. PRD-08 checks every invariant; no v5 reader (PRD-08 line 21).
- **F2, long window.** PRD-01 section 12 (480-496) and PRD-06 section 2 build level 3, `window_log` 27, long
  matching, written at record time; readers decode with `--long=27` (PRD-01 519, PRD-07 section 7, PRD-12
  594). Only the "may drop to 26" escape hatch is wrong (L4-2).
- **M1, the core.** URL password rule (PRD-05 section 5), email rule dropped (section 8 row 1, K12 stated loss
  in PRD-17 209), Codex rows dropped (PRD-11 line 742 and the new Codex file at 427-431), left guard with
  escape, percent and ANSI exceptions so `\nsk-...` still masks and never a plain `\b` (section 4), every
  other shared literal kept (20 literals = 23 today minus email minus 3 `proxy_credential` plus
  `url_password`; `proxy_credential` goes only because 1.0 has no proxy credential, PRD-00 173). Masking runs
  in memory before any byte reaches a queue to disk (PRD-05 section 1; PRD-02 calls the masker; meta through
  `mask_meta`). Header name rule, `Bearer`/`Basic`, URL userinfo and bare-CR rules kept.
- **U1, upload.** PRD-06 sections 4, 5, 7: a round every 5 minutes or at once at 16 MiB compressed, chunks at
  most 32 MiB; backoff 2 s doubling, capped at 120 s, reset whenever the server's offset moves; prune of a
  closed part once a confirmed offset passes its end, prefix only, no 2-hour timer, no disk branch. Proven by
  U2, U3, U5 and `upload_backoff.rs`, `upload_prune.rs`. `GOALCUP_KEEP_PARTS=1` on test runs is a stated
  default, harmless for participants.
- **S1, together.** PRD-07 and PRD-08 move to GCR1 in this build with no backward compatibility; first staging
  deploy only after PRD-07 step 2 and PRD-06 merge (PRD-07 section 12, PRD-16 186-191); production deploy is
  the owner's, release first, then the Worker with the 1.0.0 floor.
- **S2, usage stats.** PRD-09: model, input, cached, output and reasoning tokens, status per call, and per
  thread (subagent) models, calls and tokens; made by `goalcup-verify usage` after upload on an organizer
  machine; client-at-finish option rejected (PRD-09 section 1). No usage parsing in PRD-02, PRD-03, PRD-04 or
  PRD-10 (checked by grep; PRD-03 line 54 says the recorder never reads model names).
- **S3, no migration.** PRD-07 section 11: `{}` in `chunks.ack`, final head in both digest columns, counts in
  `heartbeats.vitals` nested under `counts`, `connector_sha256` in both digest columns, usage JSON in a
  separate R2 bucket; `server/worker/sql/**` untouched (PRD-07 "Must not touch", PRD-13 234). The test
  bucket is the existing `goalcup-traces-staging`, which the ledger allows (it permits, not requires, a
  separate one).
- **BUILD-PROMPT.md.** Section 2 and 43-44 restate staging, R2 bucket permission and no migration; it defers
  masking and format to the ledger and PRDs; nothing in it conflicts with section 4.
