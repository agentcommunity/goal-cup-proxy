FAILURES AND OWNERS
F1 OWNER PRD-12 rig (and its rung-5 design). scripts/pad/pad-run:343-346: tmux runs `bash launch.sh` as the pane command, and goalcup start
   (the watchdog) is that shell's last command. kill -9 of the watchdog ends launch.sh, the pane's session leader exits, and the harness
   (in the watchdog's process group, PRD-02 section 8 step 4) loses its terminal and exits within seconds. The recorder then seals
   harness_exit, so both recover outcomes cannot be what PRD-12:357 expects. PRD-02 9.1 and PRD-12:1053 predict this. PRD-10 acceptance 11
   says to rerun on a harness started without a TUI; the pad has none for Claude Code or Codex. With an interactive participant shell the
   shell takes the foreground back (PRD-02 9.1), so the harness is lost there too. The r5t variant (L3) shows recover itself is sound.
   Decision for the owner: accept L3 as the rung-5 setup ("terminal kept"), or add a non-TUI connector copy for P12.

   On r5t-codex the status line about unrecorded ab.chatgpt.com ("run goalcup seal, then goalcup continue") matched, so a clean recover row
   became faults INCONCLUSIVE. Fix: match only the state line "To go on, run: goalcup continue" in the status fault, or the PROBLEM line.
