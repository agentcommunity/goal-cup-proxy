## 6 Risks

### 6a The exact-value masking design (ledger 17:45Z)

Does it respect the rules? It reads no file and hands nothing to the harness, so it keeps "reads no secret files" on the letter.
It does not avoid handling keys: the recorder would hold and match them, as the watchdog already does for `GH_TOKEN`. Its risks:

1. **It covers the wrong values.** Learned from auth headers, it masks provider and gateway keys, which already have shape rules
   (`sk-`, Anthropic, `AIza`, `AQ.`, the gateway literals of `fc8df0e9`) and are masked by header name. It misses every leak
   that raised question 3: the `.env` values that `cat .env` prints (the pad's `PAD_SECRET_PLAIN`, plain hits 9, 98, 8 and 76 on
   the four Hermes rows; Stripe-like keys in the payments prompt) and the W1 password, which sits in `.git/config` and is never
   an auth header. PRD-00 question 3 names `cat .env` as the biggest real leak path.
2. **Values die with the recorder.** The masker's policy is fixed when it is built (`mask/mod.rs:107-136`, an
   `Arc<stream::Policy>`, built at `pipeline/mod.rs:820` from the control line). Start-time values survive restarts because the
   watchdog resends them; wire-learned values live in the recorder, so after every restart (R3) and every `goalcup recover` (R3b)
   nothing is masked by value until the next call, and native snapshots taken before the first call are never covered. Fixing
   that means the recorder sends keys up to the watchdog: a new key path.
3. **Point 3 cost.** Values added mid-run make the policy mutable under live streams, compile up to 11 wrapped regexes per value
   in the relay process, and need a rule for rotating tokens past the 32-value guard. PRD-05 section 9 says no value is added
   during a run; the format note `mask_values` would be written for the first time. All of it in the hot path, 2 days before the
   freeze.
4. **"Across deltas" is parsing in the recorder** (R8 and D3: record raw), per provider event shape, and it changes no observed
   row: every deltas-only hit so far had 0 known values, so they are model-written shapes, not known secrets.
5. **Native SQLite stays uncovered either way.** Trigram index pieces, and values cut by overflow-page or WAL frame headers, are
   seen by no exact or shape rule. Dropping `state.db` is the right call for Hermes. OpenCode's and OpenClaw's SQLite copies carry
   the same class: a stated limit in PRD-05 and the participant text, or the same drop.

Recommended instead: step 2 (sources 1 to 3). Values only from what goalcup already holds or already opens, no recorder change,
inside the owner's yes. Confirm with the owner in one line and have the owner record M1a.
