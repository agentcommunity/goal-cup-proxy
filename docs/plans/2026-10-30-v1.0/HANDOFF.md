# Handoff ledger for the goalcup 1.0 build

For any agent who picks up this build. Kept by the conductor; the "Branches" table is regenerated by
`$GC_TOOLS/handoff.sh` at each conductor wake-up. Read this first, then `NIGHT-LOG.md` (newest lines at the end).

## What this is

The build in `BUILD-PROMPT.md` (the part between its first two `---` lines), run by a conductor session that
orchestrates lane workflows. Rules that win over everything: `OWNER-DECISIONS.md`, `VISION.md`, `AGENTS.md`.
The plan: `PRD-16-orchestration-acceptance.md` (lanes, phases, merge rule, real runs, report) and
`PRD-00-index.md` (ownership, seams, build order). Every PRD has an Amendments note at its end with what
was learned; read it before planning that PRD.

## How it runs (and how to resume)

- Integration branch `v1.0/integration`; PRD branches `v1.0/prd-NN-<slug>`; task branches
  `v1.0/prd-NN-<slug>-<task>`. Nothing goes to `main`. Merge commits only, never a force push.
- Builds and tests run only in Vercel Sandboxes, never in the conductor container
  (`node $GC_TOOLS/box.mjs run --repo <dir> --ref <branch> --script <job> [--vcpus N] [--minutes N]`; needs the tools
  installed with `install.sh` (below) and `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, `VERCEL_PROJECT_ID` in env; the box
  clones the ref, runs the job as a non-root user, 8 vCPU unless `--vcpus` says less). Build snapshot: `box.mjs snapshot-build` writes `build-snapshot.id`
  (Rust 1.99, nextest, zstd, Node 22, Python 3.9; use python3.11 from dnf for scripts that need 3.10+).
- Every merge into integration goes through `$GC_TOOLS/merge.sh <branch> "<message>" [--refresh-lock]`:
  one lock, merge into a scratch worktree, `gate fast` in a build box as a non-root user, push only on
  PASS. Lanes queue merges as `$GC_NIGHT/mrq/<id>.req` JSON; `$GC_TOOLS/mergeq.sh <seconds>` drives
  the queue (waiter agents run it while they wait).
- Lane workflow script: `$GC_TOOLS/gc-lane.js` (per PRD: plan a slice, build tasks in own git worktrees
  under `$GC_WT/`, join, reviewers A and B, plus the breaker for core PRDs 01, 02, 03, 05, 06, fix
  loop, merge request, replan Amendments note). Start a lane with the Workflow tool, `scriptPath` = a copy
  of `gc-lane.js` under the session's working directory, and args like
  `{"lane":"<name>","session":"<this session URL>","paths":{"repo":...,"tools":...,"night":...,"wt":...},"prds":[{"id":"PRD-NN","slug":"prd-NN-<slug>","file":"PRD-NN-....md","core":bool,"note":"..."}]}`.
  To resume an unfinished slice from its branch, add
  `"pending":{"branch":"v1.0/prd-NN-<slug>","slice":"<what>","prepare":"<what is unfinished>","findings":[]}`
  (empty findings: a fresh review; non-empty: a fixer first).
- Lane logs: `$GC_NIGHT/lanes/<lane>.log` in the container; `$GC_TOOLS/scribe.sh` merges them into
  `NIGHT-LOG.md`. A new container starts with an empty `$GC_NIGHT`; `install.sh --night` creates the folders and restores the committed ledger.
- Agent models: reviewer A, the breaker, and core builders and fixers on the default model; routine
  coding (non-core builders, fixers, planners, joins, merge requests, replans, reviewer B) on the cheaper
  model; merge waiters on the smallest (owner's instruction, 30 Oct).
- Keys: never on disk in the conductor (the session policy blocked `~/.pad-keys/`). The pad's conductor
  half reads a key from its env var inside the process and writes it into the pad box as a 0600 file.
  `GH_TOKEN` never enters a box. No pad push token yet: rows say "push not tested".

## Sandbox proxy patch

What: the SDK file `node_modules/@vercel/sandbox/dist/api-client/base-client.js` imports `Agent` from undici.
The patch changes that ESM import to `EnvHttpProxyAgent as Agent`. The CommonJS build used by the pad's `sbx.mjs`
is covered by `proxy-preload.cjs` instead, which sets `undici.Agent = undici.EnvHttpProxyAgent`.

Why: the SDK's `undici.Agent` ignores `HTTPS_PROXY`, so behind a proxy every sandbox call fails with no clear cause.

`install.sh` applies the patch after `npm ci` (through `patch-sandbox.sh`, which exits 5 naming the file when the
SDK layout is not the pinned 3.9.1). `package.json` pins `@vercel/sandbox` to exactly 3.9.1. Redo the patch by
running `install.sh` again after any install that rewrites the module.

## Start in a new container

1. Set the secret environment variables listed in `SECRETS.md` (names only there) and check each by name.
2. `bash install.sh --dest $HOME/gc-tools --repo <primary checkout> --night $HOME/gc-night --wt $HOME/gc-wt --session <this session URL> --coauthor "<co-author line>"`.
   Add `--night` only when `$GC_NIGHT` does not exist yet; it restores the committed ledger and never replaces a file.
   The paths and the session land in `$GC_TOOLS/env.sh` (no secret value goes in it).
3. `export NODE_OPTIONS="--use-openssl-ca --no-warnings --require $GC_TOOLS/proxy-preload.cjs"` and
   `export PAD_NODE_MODULES=$GC_TOOLS/node_modules` before any `sbx.mjs` pad call.
4. `node $GC_TOOLS/box.mjs snaps` lists snapshots and running boxes; compare with `snapshots.md`.
5. Read `STATE.md`, then `NEW-SESSION-PROMPT.md`. The first ledger line is
   `Conductor resumed in a new session at <time>Z on <head>.`.

## Decisions the conductor took (night log has each line)

- Box user is `vercel-sandbox` (non-root), not `ubuntu`.
- Size-budget overage alone is a nit; the replan reports `wc -l` against PRD-00's row.
- Core PRDs get up to 6 review rounds (new real cases kept appearing each round), others 3.
- A reviewer that dies (usage limit) blocks the merge; it never counts as "no findings".
- The PRD-02 scaffold carried a placeholder `src/main.rs` for PRD-10 to replace (seam line).
- Seam S3: `LaunchPlan.unread` and `.log` (consumer PRD-10 start screen).
- The scribe runs at each conductor wake-up, not every 30 minutes (background loop limit).
- Usage-limit pauses so far: about 13:30 to 14:25Z and about 17:30 to 22:50Z on 30 Oct.
