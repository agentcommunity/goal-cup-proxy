# Releases and Homebrew

A release is four tarballs, one per target, built by
[.github/workflows/release.yml](../.github/workflows/release.yml) when a `v*` tag is pushed, and
installed with Homebrew from the `agentcommunity/tap` tap:

```sh
brew install agentcommunity/tap/goalcup
```

The binaries are unsigned and not notarized. Homebrew does not quarantine what it downloads, so
macOS runs them without a Gatekeeper prompt.

## What a release holds

| Asset | What it is |
|---|---|
| `goalcup-<version>-<target>.tar.gz` | One per target: `aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` |
| `SHA256SUMS` | `sha256sum` of each tarball |
| `goalcup.rb` | The Homebrew formula for this release, rendered from [homebrew/goalcup.rb](homebrew/goalcup.rb) |

Each tarball unpacks to one directory laid out as an install prefix, so it also runs where it is
unpacked, with no Homebrew:

```text
goalcup-<version>-<target>/
  bin/goalcup  bin/goalcup-daemon  bin/goalcup-verify
  share/goalcup/connectors/     codex-cli and claude-code-cli, exactly as committed
  LICENSE  NOTICE  THIRD-PARTY-LICENSES.md
```

`goalcup` finds the connectors as `<its own directory>/../share/goalcup/connectors`
(`connectors_dir` in `crates/goalcup-cli/src/config.rs`) and starts `goalcup-daemon` from beside
itself, so nothing is configured and nothing is written outside the install. The formula installs
the binaries into `bin` and the connectors into `share/goalcup/connectors` (`pkgshare`).
`hermes-cli` is left out: it is run by the maintainer only (H-21 in [TODO.md](../TODO.md)).
`THIRD-PARTY-LICENSES.md` holds the licence texts of every crate the binaries link for that
target, generated by [scripts/third-party-licenses.py](../scripts/third-party-licenses.py).

The Linux tarballs are built on Ubuntu 22.04 and need glibc 2.35 or later. Building one does not
mean a Linux capture works: see the README for what each platform supports.

## Cutting a release

The tag must equal the workspace version in `Cargo.toml`: the workflow refuses `v0.5.0` while
`Cargo.toml` says `0.1.0`, because the formula's test checks `goalcup --version` against it.

1. Set `version` under `[workspace.package]` in `Cargo.toml`, run the gate, merge to `main`.
2. Tag that commit and push the tag:

   ```sh
   git tag v0.5.0 && git push origin v0.5.0
   ```

3. The workflow builds the four targets, then creates the GitHub release with every asset. To
   try the build without releasing, start the workflow by hand (Actions, `release`, Run
   workflow, from `main` or a tag): it uploads the tarballs as run artifacts and publishes
   nothing. Do this once before the first tag: no part of the workflow has run yet.

## Publishing to the tap

`brew install agentcommunity/tap/goalcup` reads `Formula/goalcup.rb` from the GitHub repository
`agentcommunity/homebrew-tap`. Once, create it:

```sh
gh repo create agentcommunity/homebrew-tap --public \
  --description "Homebrew formulae for AgentCommunity"
```

For each release, copy the rendered formula into it:

```sh
gh repo clone agentcommunity/homebrew-tap && cd homebrew-tap
mkdir -p Formula
gh release download v0.5.0 --repo agentcommunity/goal-cup-tracer --pattern goalcup.rb \
  --output Formula/goalcup.rb --clobber
git add Formula/goalcup.rb && git commit -m "goalcup 0.5.0" && git push
```

Then check it from a clean shell: `brew install agentcommunity/tap/goalcup` and
`brew test goalcup`.

## Trying the formula without publishing

Package for this machine, render the formula against the local tarball, and install it from a
throwaway local tap (Homebrew refuses a formula file outside a tap). `render-formula.py` wants a
digest for all four targets; Homebrew fetches only this machine's, so the other three get a
placeholder:

```sh
export PATH="$HOME/.cargo/bin:$PATH"
export HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1
target=aarch64-apple-darwin    # x86_64-apple-darwin on an Intel Mac
version=$(sed -n 's/^version = "\(.*\)"$/\1/p' Cargo.toml | head -n 1)
cargo build --release --locked --offline --target $target \
  -p goalcup-cli -p goalcup-daemon -p goalcup-verifier
CARGO_NET_OFFLINE=true sh scripts/package-release.sh $target "$version" dist
(cd dist && shasum -a 256 *.tar.gz > SHA256SUMS)
for other in x86_64-apple-darwin aarch64-unknown-linux-gnu x86_64-unknown-linux-gnu; do
  [ $other = $target ] || printf '%064d  goalcup-%s-%s.tar.gz\n' 0 "$version" $other >> dist/SHA256SUMS
done
brew tap-new --no-git local/goalcup-test
python3 scripts/render-formula.py --version "$version" --sums dist/SHA256SUMS \
  --base-url "file://$PWD/dist" \
  > "$(brew --repository local/goalcup-test)/Formula/goalcup.rb"
brew install local/goalcup-test/goalcup
brew test local/goalcup-test/goalcup
brew audit --formula local/goalcup-test/goalcup
brew uninstall local/goalcup-test/goalcup && brew untap local/goalcup-test && rm -rf dist
```

`brew test` runs `goalcup --version` and `goalcup-verify --version`, and checks through
`goalcup doctor --json` that the installed `goalcup` finds the connectors and that each one's pin
passes.
